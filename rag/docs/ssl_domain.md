# SSL и домен

Файл предназначен для базы знаний SEOdyssey. Текст написан как практическая инструкция для RAG: меньше теории, больше диагностики, исправлений и проверяемых примеров.

### Что такое SSL-сертификат и зачем нужен

**Что это**
Что такое SSL-сертификат и зачем нужен — часть HTTPS-инфраструктуры сайта: сертификат, срок, цепочка доверия и корректная загрузка ресурсов.

**Почему важно для SEO**
Важно для SEO, потому что влияет на один или несколько базовых блоков: индексацию, ранжирование, CTR, обход сайта, доверие, поведенческие сигналы или конверсию. Если этот элемент сломан на шаблоне, проблема масштабируется сразу на десятки или тысячи URL.

**Как диагностировать**
Проверьте браузерный замок, SSL Labs, `curl -Iv https://site.ru`, Яндекс.Вебмастер и срок сертификата.

**Как исправить**
1. Найдите все URL, где проблема повторяется.
2. Определите, это единичная ошибка или ошибка шаблона/CMS.
3. Исправьте первопричину: код ответа, шаблон, мета-тег, контент, настройки сервера или данные в кабинете.
4. Проверьте исправление на 3–5 типовых URL вручную и через краулер.
5. Обновите sitemap/внутренние ссылки при необходимости и отправьте важные страницы на переобход.

**Пример правильного варианта**
```
HTTPS открывается без предупреждений, сертификат действителен, цепочка полная, HTTP редиректит на HTTPS.
```

**Пример неправильного варианта**
```
NET::ERR_CERT_EXPIRED, сертификат не на тот домен или страница грузит HTTP-ресурсы.
```

**Частые ошибки**
- Исправляют один пример URL, хотя проблема находится в шаблоне.
- Не проверяют результат после релиза.
- Оценивают только главную страницу и забывают категории, карточки и статьи.
- Используют формальное решение без проверки в Яндекс.Вебмастере, GSC или краулере.
- Не фиксируют дату изменения, поэтому потом невозможно понять, что именно повлияло на трафик.

### Типы сертификатов: DV, OV, EV, Wildcard

**Что это**
Типы сертификатов: DV, OV, EV, Wildcard — отдельный элемент SEO-проверки, который нужно оценивать не абстрактно, а по конкретным URL, шаблонам и данным из инструментов.

**Почему важно для SEO**
Важно для SEO, потому что влияет на один или несколько базовых блоков: индексацию, ранжирование, CTR, обход сайта, доверие, поведенческие сигналы или конверсию. Если этот элемент сломан на шаблоне, проблема масштабируется сразу на десятки или тысячи URL.

**Как диагностировать**
Проверьте выборку важных URL: главную, категории, карточки, статьи, страницы услуг и контакты. Используйте Screaming Frog, Яндекс.Вебмастер, Google Search Console, браузер DevTools и ручную проверку.

**Как исправить**
1. Найдите все URL, где проблема повторяется.
2. Определите, это единичная ошибка или ошибка шаблона/CMS.
3. Исправьте первопричину: код ответа, шаблон, мета-тег, контент, настройки сервера или данные в кабинете.
4. Проверьте исправление на 3–5 типовых URL вручную и через краулер.
5. Обновите sitemap/внутренние ссылки при необходимости и отправьте важные страницы на переобход.

**Пример правильного варианта**
```
Типы сертификатов: DV, OV, EV, Wildcard: настроено корректно, данные совпадают на странице, в коде и в инструментах поисковиков.
```

**Пример неправильного варианта**

**Как исправить**
1. Найдите все URL, где проблема повторяется.
2. Определите, это единичная ошибка или ошибка шаблона/CMS.
3. Исправьте первопричину: код ответа, шаблон, мета-тег, контент, настройки сервера или данные в кабинете.
4. Проверьте исправление на 3–5 типовых URL вручную и через краулер.
5. Обновите sitemap/внутренние ссылки при необходимости и отправьте важные страницы на переобход.

**Пример правильного варианта**
```
paid-till: 2027-05-12
nserver: ns1.hosting.ru
```

**Пример неправильного варианта**
```
paid-till: 2026-05-12
nserver: parking.registrar.ru
```

**Частые ошибки**
- Исправляют один пример URL, хотя проблема находится в шаблоне.
- Не проверяют результат после релиза.
- Оценивают только главную страницу и забывают категории, карточки и статьи.
- Используют формальное решение без проверки в Яндекс.Вебмастере, GSC или краулере.
- Не фиксируют дату изменения, поэтому потом невозможно понять, что именно повлияло на трафик.

### Переезд на новый домен

**Что это**
Переезд на новый домен — проверка владения, срока действия и технической доступности доменного имени.

**Почему важно для SEO**
Важно для SEO, потому что влияет на один или несколько базовых блоков: индексацию, ранжирование, CTR, обход сайта, доверие, поведенческие сигналы или конверсию. Если этот элемент сломан на шаблоне, проблема масштабируется сразу на десятки или тысячи URL.

**Как диагностировать**
Проверьте Whois, панель регистратора, DNS-записи, срок оплаты и доступность сайта.

**Как исправить**
1. Найдите все URL, где проблема повторяется.
2. Определите, это единичная ошибка или ошибка шаблона/CMS.
3. Исправьте первопричину: код ответа, шаблон, мета-тег, контент, настройки сервера или данные в кабинете.
4. Проверьте исправление на 3–5 типовых URL вручную и через краулер.
5. Обновите sitemap/внутренние ссылки при необходимости и отправьте важные страницы на переобход.

**Пример правильного варианта**
```
Домен продлён минимум на несколько месяцев, автопродление включено, DNS указывает на актуальный сервер.
```

**Пример неправильного варианта**
```
Домен просрочен, DNS сменился на парковку регистратора, сайт отдаёт заглушку.
```

**Частые ошибки**
